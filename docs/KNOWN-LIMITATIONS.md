# محدودیت‌های شناخته‌شده — 10on
1. **وابستگی‌های transitive آسیب‌پذیر (۲۵ مورد، ۲ critical در sharp/libvips):** رفع نیاز به `npm audit fix --force` (breaking) دارد؛ sharp در مسیر آپلود استفاده نمی‌شود (اعتبارسنجی نوع/حجم مستقل است). توصیه: PR جداگانه برای upgrade کنترل‌شده.
2. **دسترسی DB production از sandbox قطع است** (.env.local حاوی رشتهٔ اتصال در بازیافت محیط از بین رفت و endpoint ریست رمز Supabase روی این توکن در دسترس نیست). Production (Vercel) با متغیر خودش سالم است؛ تست‌های این سشن روی Postgres واقعی محلی اجرا شد. برای migrate resolve روی prod به پنل Supabase نیاز است.
3. **Expiry زمانی توکن** (۳۰ روز) تست زمانی ندارد — منطق امضا/ابطال پوشش داده می‌شود.
4. **سرویس AI خارجی:** در نبود کلید، عامل‌ها پیام شفاف «در دسترس نیست» می‌دهند؛ E2E عامل فقط تا مرز فراخوانی تست می‌شود.
5. **Rate limiter** آمادهٔ مهاجرت به Redis است (امضای `rateLimit` ثابت)؛ در مقیاس بسیار بالا (۱۰۰۰+ rps) پستگرس bottleneck می‌شود.
6. **Journal historical seed:** فاکتورهای دموی seed سند حسابداری تاریخی ندارند (فقط دادهٔ نمایشی)؛ تراکنش‌های واقعی همیشه سند می‌سازند.
7. **مهاجرت داده‌های واقعی:** هیچ دادهٔ واقعی بیمار در repo/seed نیست؛ data واقعی فقط در DB production است.
